# Компонент: Пульт + Графиня — мониторинг и наблюдаемость

> Слой: Observability — `ktc-obs` / `ktc-infra` | Это: сбор метрик (Пульт) + визуализация (Графиня) | Протокол: Prometheus-совместимый

## 1. Назначение

**Пульт + Графиня — «приборная панель» системы.** Собирают метрики со всех
сервисов и инфраструктурных компонентов (Picodata, Radix, NATS, MinIO, прикладные
сервисы), хранят их и визуализируют на дашбордах. Позволяют следить за состоянием
real-time контура (телеметрия 1 Гц), отказоустойчивостью (Raft, failover) и
производительностью (latency, tick-lag).

## 2. Почему именно Пульт + Графиня (обоснование выбора)

| Требование | Как закрывают Пульт + Графиня |
|---|---|
| **Отечественность** (ARCH-06) | отечественные системы, compatible с Prometheus/Grafana, РРПО |
| **Совместимость** | **Пульт** — Prometheus-совместимый сбор метрик; **Графиня** — Grafana-совместимая визуализация |
| **Интеграция** | сервисы отдают метрики в пром-формате (`/metrics`, `sharedmetrics`) — без доп. экспортеров |
| **Единый стек** | один контур наблюдаемости для приложений и инфраструктуры |

## 3. Использование в коде / метрики

Сервисы уже отдают метрики в Prometheus-формате:
- **Пульт** — сбор метрик (scrape `/metrics` с каждого сервиса + инфраструктуры).
- **Графиня** — дашборды (Grafana-совместимая).

В Go-сервисах метрики отдаются через общий пакет `sharedmetrics`
(`middleware` + `/metrics`), например: количество созданных/запущенных/остановленных
сессий, введённых неисправностей, действий оператора, чекпоинтов.

**Ключевые дашборды/метрики по компонентам:**

| Компонент | Метрики в Пульт + Графиня |
|---|---|
| `orchestrator` | количество/статус сессий, tick-lag, WS-подключения, задержка sim.step, cache hit-miss |
| `sim` | загрузка CPU (1 Гц), tick (≥1 Гц), per-session поды |
| `Picodata` | статус Raft, failover, лаг репликации, запросы/сек, размер БД |
| `Radix` | hit-miss ratio, размер, задержка чтения/записи, TTL-протухшие |
| `NATS` | длина стримов, rate, задержка доставки |
| `MinIO` | объём, число объектов, скорость put/get |
| `gw`/BFF | через пром-метрики (`Angie` — нативный `/status`) |
| Платформа | CPU/GPU/память узлов, Raft status (см. схему: «метрики: tick-lag, WS, CPU/GPU, Raft status») |

## 4. Логирование и связь с SIEM

- **Логирование**: Fluent Bit → Пульт (контур наблюдаемости). Подробнее — [fluent_bit.md](fluent_bit.md).
- **Аудит ИБ**: события аутентификации и админ-действий → Kaspersky **KUMA** (SIEM),
  интенсively в `gw`/`auth` (единственная точка входа).

## 5. Размещение

- Отдельный слой `ktc-obs`/`ktc-infra` — отдельный namespace: Пульт, Графиня,
  Fluent Bit, NATS.
- Пром-скрейп идёт из этого контура ко всем сервисам и инфраструктуре.

## 6. Объекты Kubernetes

| Объект | Описание |
|---|---|
| Deployment `pult` | коллектор метрик (Prometheus-совместимый), long-term storage |
| Deployment `grafinya` | дашборды и алертинг (Grafana-совместимая) |
| DaemonSet `fluent-bit` | сбор логов |
| Service/PVCs | хранилище метрик |

## 7. Отказоустойчивость / масштабирование

- Ретининг метрик в Пульт; репликация при необходимости.
- Алертинг (правила) в Графине на критические события (failover, tick-lag, очередь NATS).

## 8. Открытые вопросы

1. Политика хранения метрик (ретеншн long-term vs short-term).
2. Набор стандартных дашбордов и алертов для real-time контура.
3. Интеграция метрик с оценкой производительности (PERF/NFR метрики) для отчёта.
