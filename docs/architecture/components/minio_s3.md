# Компонент: MinIO (S3-объектное хранилище)

> Слой: Данных — `ktc-data` | Это: объектное хранилище (S3-совместимое, on-prem) | Протокол: S3 API

## 1. Назначение

**MinIO — «склад крупных файлов».** Хранит большие бинарные объекты, которые
неуместно класть в строковую СУБД: снапшоты сессий (payload), PDF-отчёты и протоколы
экзаменов, иконки/SVG компонентов. Пикодата хранит **метаданные** этих объектов
(где лежит, SHA-256), а сам контент — в MinIO.

## 2. Почему именно S3/MinIO (обоснование выбора)

| Требование | Как закрывает MinIO |
|---|---|
| **Объём** | объектное хранилище, ёмкости под ≥10 000 снапшотов |
| **Иммутабельность** | объекты неизменяемые (write-once), для протоколов/снапшотов важна целостность |
| **Совместимость** | S3 API — стандартный интерфейс, работает `minio-go` и большинство SDK |
| **Целостность** | SHA-256 объекта хранится в Picodata; проверка при restore |
| **On-prem / отечественность** | разворачивается в кластере; target — отечественное решение (MinIO — прототип/S3-совместимый) |

## 3. Использование в коде

Реализация — `services/go/snapshot/internal/storage/s3.go` (клиент
`github.com/minio/minio-go/v7`), конфиг — `internal/config/config.go`.

| Сервис | Что хранит в S3 |
|---|---|
| `snapshot` | **payload снапшотов** сессий (полное состояние модели, контуры, алармы) |
| `report` | **PDF-отчёты** и протоколы экзаменов |
| `constructor` | **иконки/SVG** библиотеки компонентов |

**Модель «метаданные в БД + payload в S3»**:
- `Snapshot`: метаданные (id, session_id, model_time, SHA-256, storage_key) — в
  Picodata, payload (бинарное состояние) — в MinIO по `storage_key`.
- `ExamProtocol`: канонический JSON + HMAC-подпись — в Picodata, PDF — в MinIO.

## 4. Размещение

- Слой данных `ktc-data`, отдельный сервис в data-plane.
- Доступ только из прикладных сервисов (`snapshot`, `report`, `constructor`),
  через mTLS + NetworkPolicy.

## 5. Объекты Kubernetes

| Объект | Описание |
|---|---|
| Deployment/StatefulSet `minio` | объектное хранилище (S3 API) |
| Service `minio` | ClusterIP |
| PersistentVolume(s) | объекты на большой ёмкости |
| Secret | ключи доступа (access/secret key) |
| Buckets | `snapshots`, `reports`, `icons` |

## 6. Метрики (в Пульт + Графиня)

- Объём хранилища по bucket-ам, число объектов.
- Скорость/задержка put/get, ошибки/ретраи.
- Квоты bucket-ов (снапшоты ≥10 000).

## 7. Отказоустойчивость / масштабирование

- Erasure coding / репликация объектов MinIO.
- Иммутабельные объекты — безопасны для перезаписи.
- Масштабирование ёмкости добавлением серверов в распределённый режим.

## 8. Открытые вопросы

1. Target-решение для объектного хранилища (MinIO как прототип, отечественная замена).
2. Политика хранения/удаления старых снапшотов и отчётов (retention, life-cycle).
3. Резервное копирование bucket-ов.
