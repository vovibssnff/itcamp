# Требования информационной безопасности КТК ЭЛОУ-АВТ

## Термины и сокращения

| Сокращение | Расшифровка |
|---|---|
| **КТК** | Компьютерный тренажёрный комплекс |
| **ЭЛОУ-АВТ** | Тип технологической установки (электрообессоливающая установка / атмосферно-вакуумная трубчатка), на базе которой построен сценарий тренажёра |
| **НСД** | Несанкционированный доступ |
| **ПДн** | Персональные данные |
| **ИС** | Информационная система |
| **ИСПДн** | Информационная система персональных данных |
| **КИИ** | Критическая информационная инфраструктура |
| **ОПО** | Опасный производственный объект |
| **АСУ ТП** | Автоматизированная система управления технологическим процессом |
| **ФСТЭК** | Федеральная служба по техническому и экспортному контролю |
| **PAM** | Privileged Access Management — система контроля привилегированного доступа |
| **SIEM** | Security Information and Event Management — система сбора и анализа событий ИБ |
| **LDAP** | Lightweight Directory Access Protocol — протокол доступа к каталогу учётных записей |
| **RBAC** | Role-Based Access Control — управление доступом на основе ролей |
| **SBOM** | Software Bill of Materials — спецификация состава программного обеспечения |
| **2FA / TOTP** | Двухфакторная аутентификация / одноразовые пароли по времени |
| **CSP / SRI** | Content Security Policy (политика безопасности контента) / Subresource Integrity (проверка целостности подключаемых ресурсов) |
| **XSS / SQL** | Межсайтовый скриптинг / язык запросов к базам данных |
| **ИИ** | Искусственный интеллект |
| **AES / TLS / SHA** | Алгоритмы шифрования, транспортной защиты и хеширования |
| **СКУД** | Система контроля и управления доступом |
| **VLAN / IP / ПК** | Виртуальная локальная сеть / сетевой протокол / персональный компьютер |

## 1. Тип обрабатываемых данных и уровень защищённости

| Параметр                    | Значение                                                                                                                                                                                                                                                                                                                                                                                   |
|-----------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Категория данных**        | Учебно-тренировочные данные (сценарии обучения, результаты экзаменов, журналы действий, ПДн)                                                                                                                                                                                                                                                                                               |
| **Гриф конфиденциальности** | Сценарии и модели — **«Коммерческая тайна»** (ФЗ-98 «О коммерческой тайне», Указ Президента РФ №188, п. 5); оперативные данные обучения (результаты экзаменов, журналы) — **«Конфиденциально»**. Гриф «Коммерческая тайна» наносится на носители/документы **с указанием обладателя (полное наименование и место нахождения организации)** в соответствии со ст. 10 ФЗ-98. Режим коммерческой тайны устанавливается правообладателем при выполнении мер, предусмотренных ст. 10 ФЗ-98 (определение перечня сведений, ограничение доступа, учёт лиц, регулирование трудовых/гражданско-правовых отношений, нанесение грифа). Состав этих мер для КТК — в разделе 3.3. |
| **Уровень защищённости**    | Класс **У3** (условно защищённая ИС) по Приказу ФСТЭК №17. КТК — обучающий тренажёр, **не является АСУ ТП** (не управляет технологическим процессом). Вопрос отнесения к объектам КИИ решается по ПП №127 «Правила категорирования»; при отнесении КТК к КИИ принимается консервативная **категория 3**. Детальное обоснование класса — в Приложении.                                                                                                                                                                                                                                                                                                                                                                                   |
| **Класс ИСПДн**             | **Да** (обрабатываются ПДн). Система хранит ФИО операторов, результаты экзаменов, историю обучения — персональные данные в смысле ФЗ-152.                                                                                                                                                                                                                                                  |
| **Применимые НПА**          | ФЗ-187 «О безопасности КИИ», ПП РФ №127 (категорирование КИИ), Приказ ФСТЭК №17 (класс У3), ФЗ-152 «О персональных данных», ФЗ-98 «О коммерческой тайне», ГОСТ Р 57700.37-2021 (цифровые двойники)                                                                                                                                                                         |

## 2. Перечень угроз и их источников

Актуальность угроз определяет модель угроз КТК. В колонке «Обоснование» указано, **почему угроза актуальна для КТК** и на какой нормативный акт опирается.

| № | Угроза | Источник (внешний / внутренний) | Объект воздействия | Обоснование актуальности |
|---|---|---|---|---|
| 1 | **НСД к проприетарным сценариям и моделям** | Внешний — злоумышленник; внутренний — ученик, инструктор, администратор | База данных сценариев, ИИ-модели | Ключевая ценность КТК — проприетарные сценарии. Их защита обязательна в режиме коммерческой тайны (ФЗ-98). Доступ сотрудников контролируется по ролям (RBAC) и PAM для привилегированных ролей |
| 2 | **Утечка результатов экзаменов и ПДн** | Внешний — атака; внутренний — администратор, инструктор | База данных ПДн, журналы обучения | Обработка ПДн требует защиты по ФЗ-152; утечка влечёт административную/уголовную ответственность и репутационные риски |
| 3 | **Компрометация / неавторизованный доступ учётных записей** | Внешний — фишинг, перебор паролей, брутфорс; внутренний — преднамеренные действия сотрудника | Система аутентификации, учётные записи операторов, инструкторов, администраторов | Компрометация привилегированных учёток (инструктора, администратора) даёт доступ к управлению сценариями и данным. Митигируется 2FA и единой аутентификацией (LDAP) |
| 4 | **Подмена сценариев / моделей** | Внутренний — сотрудник с доступом к CI/CD; внешний — атака на репозиторий | Репозиторий сценариев, модель ИИ | Утрата целостности обучающих материалов снижает качество обучения и безопасность процесса. Требует контроля целостности (хеши, подписи) и доверенного репозитория |
| 5 | **Нарушение целостности логов** | Внутренний — администратор | Журналы действий, журналы аудита | Целостность журналов необходима для расследований и аудита; защита от модификации пишет в write-once / контролируемое хранилище |
| 6 | **Социальная инженерия (на админов, инструкторов, учеников)** | Внешний — звонки, письма, имитация поддержки | Пользователи системы | Слабое звено — человеческий фактор; требуется обучение персонала и политика информационной безопасности |
| 7 | **Атаки на API endpoints** | Внешний — сканеры уязвимостей, ботнеты | REST API | Инъекции, массовое извлечение данных; митигируется валидацией входа, rate limiting, WAF |
| 8 | **Отказ в обслуживании / нарушение доступности** | Внешний — DoS/DDoS; внутренний — сбой оборудования, ПО, перегрузка | Веб-сервер, БД, сервер КТК | Простой тренажёра снижает качество обучения и его доступность. Отказоустойчивость БД (репликация, резервирование) и мониторинг доступности обязательны |

## 3. Требования ИБ к программным и аппаратным компонентам

### 3.1 Общие требования

- Все компоненты КТК должны разрабатываться по стандартам secure SDLC (ГОСТ Р 57700.10-2016).
- **Обязательное использование Astra Linux SE 1.8** для всех серверных компонентов КТК — требование ФСТЭК для категорированных КИИ.
- Использование исключительно лицензионного ПО, включённого (где применимо) в Единый реестр отечественного ПО.
- Учет и мониторинг всех подключаемых библиотек и зависимостей (SBOM для зависимостей) с формированием спецификации состава ПО и контролем уязвимостей.
- Размещение библиотек и артефактов в **доверенном корпоративном репозитории** (отечественном, например GitFlic / внутреннее зеркало), без прямого использования внешних публичных ресурсов (GitHub и аналогов) из сегмента КТК.
- Организация доверенного репозитория для обновлений ПО внутри корпоративной сети (без прямого доступа в интернет из сегмента КТК).
- Обновления доставляются через локальный репозиторий с проверкой **цифровой подписи** (криптопровайдер, совместимый с ГОСТ) и контрольной суммы (например SHA-256).
- **Антивирусная защита** на всех серверных и клиентских компонентах (сервер КТК, веб-сервер, БД-хосты, учебные ПК) — сертифицированное российское антивирусное ПО (например Kaspersky Endpoint Security / Dr.Web) с регулярным обновлением баз.

### 3.2 Компоненты

| Компонент       | Требование ИБ                                                                                                                                                                                                                                                        |
|-----------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Виртуализация** | Развёртывание в частном облаке на платформе **ВК Cloud** (российская платформа виртуализации). Компоненты КТК разносятся по отдельным виртуальным машинам (ВМ), каждой — отдельный внутренний IP-адрес в изолированном сегменте сети; доступ между сегментами — по политике межсетевого экрана. Гипервизоры — доверенные (ВК Cloud / Zvirt / Arena) |
| **Сервер КТК**  | Изолированный сегмент корпоративной сети (VLAN); физический доступ по пропускной системе; **ОС: Astra Linux SE 1.8 («Воронеж»)** — обязательно для категорированных КИИ; запуск под ограниченным пользователем (не root/admin). |
| **База данных** | Отказоустойчивая конфигурация: БД размещается **на двух (и более) виртуальных машинах на разных гипервизорах/узлах** с активной репликацией (кластер) — при отказе одного узла нагрузку подхватывает другой. Шифрование данных сценариев (AES-256); резервное копирование ежедневно (хранение 365 дней, off-site копия); контроль целостности критических таблиц (SHA-256). |
| **Веб-сервер**  | HTTPS (TLS 1.2+, запрет слабых шифров), Content Security Policy (CSP) для защиты от XSS, строгая валидация входных данных, защита от SQL-инъекций (prepared statements); **антивирусное ПО/EDR** (например Kaspersky Endpoint Security) на хосте; для детекции целенаправленных атак — **Kaspersky Threat Intelligence / Anti-APT** (обнаружение вторжений и угроз по данным threat intelligence). |
| **Учебные ПК**  | Antivirus (лицензионный, например Kaspersky Endpoint Security / Dr.Web Enterprise Security Suite); очистка кэша браузера после сессии; отключение USB-масс-устройств при отсутствии необходимости (не обязательно жёсткая блокировка). |
| **ИИ-модуль**   | Контроль целостности модели (хеширование при загрузке); версионирование; аудит входных данных; изолированный сервисный аккаунт без сетевого доступа вовне. |
| **API**         | Rate limiting (50 запросов/мин на endpoint); токен-аутентификация (JWT с коротким сроком действия); логирование всех запросов. |

### 3.3 Охрана конфиденциальности коммерческой тайны (ст. 10 ФЗ-98)

Режим коммерческой тайны в отношении сценариев и моделей КТК считается установленным после принятия обладателем мер по ст. 10 ФЗ-98. Для КТК определяется следующий состав мер:

| Мера (ст. 10 ФЗ-98) | Реализация для КТК |
|---|---|
| 1) Определение перечня информации, составляющей коммерческую тайну | Утверждается перечень: проприетарные сценарии КТК, модели ИИ, параметры технологического процесса ЭЛОУ-АВТ |
| 2) Ограничение доступа (порядок обращения + контроль) | RBAC по ролям, разнесение компонентов по сегментам, изолированный доступ к репозиторию сценариев и БД |
| 3) Учёт лиц, получивших доступ / которым передана информация | Журнал аудита доступа к сценариям и моделям; регистрация выдачи прав (LDAP/AD, PAM для привилегированных ролей) |
| 4) Регулирование отношений (трудовые/гражданско-правовые договоры) | Включение условий о неразглашении в трудовые договоры персонала и соглашения с контрагентами (NDA) |
| 5) Нанесение грифа «Коммерческая тайна» с указанием обладателя | Гриф на носителях и реквизитах документов: «Коммерческая тайна» + полное наименование и место нахождения организации-обладателя |
| Дополнительно (ч. 4 ст. 10) | Средства технической защиты: шифрование (AES-256), контроль целостности (подписи, SHA-256), антивирус/EDR, SIEM |

**Разумная достаточность мер (ч. 5 ст. 10 ФЗ-98):** обеспечение исключения доступа к информации без согласия обладателя и возможность использования информации работниками/контрагентами без нарушения режима коммерческой тайны.

## 4. Технические решения (ОС, сеть, разграничение доступа)

### 4.1 Разграничение доступа по ролям

| Роль                   | Доступ                                                                 | Доп. ограничения                                                     |
|------------------------|------------------------------------------------------------------------|----------------------------------------------------------------------|
| **Ученик**             | Запуск сценариев, просмотр мнемосхемы, управление в рамках сценария    | Нет доступа к сценариям, результатам других учеников, настройкам     |
| **Инструктор**         | Создание копий сценариев и редактирование **только собственных копий**; просмотр результатов группы, оценка | Не имеет прав изменять/удалять оригинальные (готовые) шаблоны сценариев; просмотр/правка чужих копий; нет доступа к root ОС, БД напрямую, удалению учеников |
| **Администратор** (роль КТК) | Управление тренажёрным комплексом: пользователи и роли, политика оценки, контроль учебного контента, учебный аудит | Нет доступа к учебным сессиям и результатам оценки (разделение прав); не занимается инфраструктурой (бэкапы, обновление ПО, сервер — см. системный администратор) |
| **Системный администратор** (операционная роль, вне RBAC) | Резервное копирование, обновление ПО, эксплуатация сервера/кластера | Через отечественный PAM + 2FA; не имеет доступа к данным обучения и результатам оценки (разделение прав) |
| **Наблюдатель (гостевой)** | Read-only просмотр активных сессий обучения                          | Нет права изменять параметры, сценарии и результаты; доступ по времени проведения сессии (например, для внешних наблюдателей/демонстраций заказчику) |
| **ИИ-модуль (сервис)** | Чтение/запись журналов действий; чтение сценариев                      | Изолированный сервисный аккаунт, без сетевого доступа вовне          |

### 4.2 Безопасность веб-приложения

- Принудительное использование HTTPS.
- Сессии: HTTP-only, Secure cookies, таймаут неактивности — **15 минут** (настраиваемый параметр; для обучающей системы 30 минут считается избыточным, т.к. сессия интерактивная).
- Аутентификация: **единая для всех ролей через LDAP / Active Directory** (ученик, инструктор, администратор, наблюдатель).
- Двухфакторная аутентификация (2FA) для **Инструктора и Администратора (роль КТК)** — пароль + OTP/TOTP. Контроль привилегированного доступа **системного администратора** (операционная роль, вне RBAC) выполняется через **отечественный PAM** (например Solar inRBAC) с обязательной 2FA при подключении к административным учёткам.
- Rate limiting на endpoint авторизации (не более 10 попыток в минуту).
- Логирование всех действий с меткой времени и ID пользователя.
- Разделение прав на уровне бэкенда (RBAC) — проверка прав при каждом запросе.
- Content Security Policy (CSP) — mitigation для XSS.
- Subresource Integrity (SRI) для статических JS/CSS (если подгружаются извне).

## 5. Безопасность алгоритмов ИИ, мониторинг, реагирование

### 5.1 Защита моделей ИИ

| Мера                         | Описание                                                                                                                       |
|------------------------------|--------------------------------------------------------------------------------------------------------------------------------|
| **Контроль целостности**     | Хеширование каждого релиза модели; проверка при загрузке                                                                       |
| **Версионирование**          | Все модели хранятся с версией и метаданными (дата, автор, обучающая выборка)                                                   |
| **Защита обучающих данных**  | Обучающая выборка не содержит реальных регламентов (только учебные обезличенные данные)                                        |
| **Мониторинг дрейфа модели** | Автоматическое отслеживание отклонений в выводах ИИ (простая статистика). При превышении порога — оповещение администратора. |
| **Аудит решений ИИ**         | Логирование каждого вывода ИИ (input → output → confidence score)                                                              |
| **Откат модели**             | Механизм rollback к предыдущей версии модели без остановки КТК                                                                 |

### 5.2 Мониторинг и аудит

- **SIEM-система**: **MaxPatrol SIEM (Positive Technologies)** — отечественное решение, включённое в Единый реестр российского ПО. Собирает и коррелирует события со всех компонентов КТК.
- **Источники данных для SIEM** (перечень, откуда берутся события):
  - Журналы аутентификации и действий пользователей (LDAP/AD, приложение КТК);
  - Логи веб-сервера (запросы, ошибки, попытки авторизации);
  - Логи СУБД (запросы на чтение/изменение, экспорт данных);
  - События операционных систем серверов (Astra Linux);
  - Антивирусное ПО и EDR (обнаружения, карантин, подозрительная активность) — мониторинг по SNMP/агентам;
  - События межсетевого экрана и сетевого оборудования (трафик, попытки доступа) — SNMP, NetFlow;
  - Данные Kaspersky Threat Intelligence / Anti-APT (детекция целевых атак);
  - Журналы PAM (привилегированные сеансы системного администратора — операционная роль вне RBAC платформы);
  - Метрики доступности и нагрузки хостов/БД (SNMP-мониторинг).
- **Обязательные события аудита**:
  - Вход/выход пользователей
  - Изменение сценариев и моделей
  - Действия администратора (создание/удаление учёток, изменение прав)
  - Запуск/остановка сессий
  - Ошибки аутентификации (более 5 неудачных попыток)
  - Выгрузка/экспорт данных (сценарии, результаты)
- Аудит действий пользователей хранится не менее **1 года (365 дней)** — достаточно для расследования инцидентов, проверок и требований к инцидент-менеджменту, при этом журналы компактны по объёму.
- Журнал аудита защищён от модификации (write-once хранилище или файловые права + контрольные хеши).

### 5.3 Реагирование на инциденты

| Стадия             | Действие                                                                         |
|--------------------|----------------------------------------------------------------------------------|
| **Обнаружение**    | Выявление инцидента по корреляции событий в **MaxPatrol SIEM**, алертам антивируса/EDR и Kaspersky Threat Intelligence, метрикам SNMP-мониторинга (аномалии доступности/нагрузки). Все источники (раздел 5.2) передают события в SIEM в режиме, близком к real-time. |
| **Локализация**    | Отключение скомпрометированной учётной записи; изоляция затронутого сегмента/узла (если критично); приостановка затронутого сервиса |
| **Анализ**         | Формирование временной шкалы инцидента (forensic timeline) по данным из SIEM и журналам; определение первопричины, вектора атаки и затронутых объектов; фиксация собранных артефактов для возможного расследования |
| **Устранение**     | Rollback модели/сценария до последней корректной версии; смена паролей/деактивация учёток; переустановка/обновление скомпрометированного ПО |
| **Восстановление** | Восстановление данных и сервисов из резервных копий; **проверка целостности и функциональности** компонентов (восстановление работоспособности КТК). При существенных изменениях конфигурации/инфраструктуры — **повторная аттестация ИС по требованиям ФСТЭК** (если система категорирована) |
| **Пост-анализ**    | Разбор инцидента, корректировка правил корреляции SIEM и мониторинга; обновление политик ИБ и модели угроз (при необходимости) |

### 5.4 Физическая безопасность

- Сервер КТК размещается в серверной с контролем доступа (СКУД) — обязательное требование при категорировании как КИИ.
- Учебный класс — видеонаблюдение, закрывается на ключ в нерабочее время.
- Учебные ПК — программная блокировка USB-масс-устройств (по корпоративной политике).
- Пломбирование системного блока сервера — при категорировании КИИ Категории 2-3 рекомендуется обязательным.

## Приложение: Обоснование классификации КТК и выбора уровня защищённости

### 1. Категорирование объекта КИИ (если КТК признаётся объектом КИИ)

Категорирование КТК как объекта КИИ выполняется по **Постановлению Правительства РФ № 127 от 08.02.2018** (Правила категорирования), которое конкретизирует ст. 7 ФЗ-187. Категория значимости (1, 2 или 3) определяется по критериям значимости (социальной, политической, экономической значимости, техногенным и экологическим последствиям). Для КТК обоснование следующее:

| Критерий (по Правилам категорирования, ПП №127) | Оценка для КТК | Вывод |
|---|---|---|
| Тип субъекта КИИ / связь с ОПО | КТК использует модели технологического процесса ЭЛОУ-АВТ (связан с ОПО), но **не является АСУ ТП** и не управляет процессом напрямую | Опосредованная связь — КТК не подлежит обязательному категорированию как значимый объект, так как не выполняет управляющие функции на ОПО |
| Социальная/экономическая значимость | Обучающий (учебно-тренировочный) характер; аварии и сбои КТК не приводят к техногенным/экологическим последствиям | Незначимая/низкая категория |
| *Итог по КИИ* | При отнесении КТК к КИИ — **категория 3** (наименьшая значимость), при условии официального категорирования по ПП №127 | Категория 3 (значимый объект КИИ) либо выведение из-под КИИ при формальном решении |

**Вывод:** КТК как учебный тренажёр не является значимым объектом КИИ в строгом смысле (не влияет на безопасность ОПО). Окончательное решение о категорировании принимается субъектом КИИ по ПП №127. В проектных/учебных целях принят **консервативный подход — уровень защищённости не ниже У3**, что гарантирует достаточность мер даже при последующем отнесении к КИИ.

### 2. Уровень защищённости (класс) — почему У3

Уровень защищённости **У3** выбран по **Приказу ФСТЭК России № 17 от 11.02.2013** (Требования о защите информации, не составляющей государственную тайну, в ГИС) — классификация информационных систем. Обоснование по критериям приказа:

| Критерий выбора уровня У3 | Соответствие КТК | Обоснование |
|---|---|---|
| Масштаб и категория обрабатываемых данных | КТК обрабатывает ПДн (категория до 2-й) и служебную/коммерческую информацию | Соответствует нижним уровням защищённости |
| Уровень значимости (К1, К2, К3) | По ФЗ-152/ФЗ-149 ущерб от нарушения конфиденциальности/целостности/доступности ограничен | Соответствует К3/У3 |
| Обработка гостайны | Не обрабатывается | Не повышает уровень |
| *Итог* | **У3** — базовый уровень защищённости для ИС, где ущерб от нарушения свойств информации ограничен, без категорированного КИИ и гостайны | У3 достаточен для учебного тренажёра |

### 3. Соответствие мер по Приказу ФСТЭК №239 (при отнесении к КИИ категории 3)

| Группа мер (по №239) | Меры, предусмотренные в требованиях КТК |
|---|---|
| Идентификация и аутентификация | Единая аутентификация LDAP, 2FA для инструктора/администратора (роль КТК), PAM для системного администратора |
| Управление доступом | RBAC с разделением прав ролей (ученик/инструктор/администратор/наблюдатель) |
| Ограничение программной среды | Доверенный корпоративный репозиторий, SBOM, контроль целостности ПО |
| Защита среды виртуализации | ВК Cloud, изоляция сегментов, отказоустойчивая БД на разных гипервизорах |
| Защита средств мониторинга | MaxPatrol SIEM, источники данных (раздел 5.2), антивирус/EDR, Kaspersky Threat Intelligence |
| Управление конфигурацией | Версионирование модели, rollback, контроль целостности (SHA-256, подписи) |
| Реагирование на инциденты | Жизненный цикл инцидента (раздел 5.3), хранение аудита 1 год |
