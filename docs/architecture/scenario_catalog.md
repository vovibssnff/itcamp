# Сервис: Scenario / Catalog Service — `scenario`

> Слой: Прикладной | Namespace: `ktc-app` | Под: `scenario`
> Смежно: `Реестр_сервисов...`, `Сценарии_экзамен...`, `Архитектура_КТК_K8s.drawio`

## 1. Назначение

**Библиотека и каталог** учебных сценариев, моделей и эталонов. Управляет «коммерческой тайной» (модели/сценарии являются ценным активом) и Low-Code-конструктором.

## 2. Основные функции

- Хранение и versioning сценариев, шаблонов техпроцесса, **каталога аварий** и эталонов оценки.
- **Low-Code-конструктор** сценариев (сборка из шаблонов).
- **RBAC**: инструктор правит только свои копии; разделение прав на запись.
- Контроль **целостности/подписей** моделей и сценариев (SHA-256/подписи ГОСТ при обновлении).
- Экзаменационные сценарии: случайная выдача оркестратору.

## 3. Технологии

Python/FastAPI. Хранилище сценарных JSON/артефактов в S3, метаданные в Picodata.

## 4. Внутренняя структура

- Менеджер каталога (CRUD сценарных сущностей).
- Конструктор сценариев (редактор/валидатор).
- Экспорт «готового сценария с эталоном» оркестратору.
- Модуль подписи/проверки целостности.

## 5. API / контракты

| Направление | Протокол | Методы |
|---|---|---|
| от `gw` | HTTPS/REST | `GET/POST/PUT /scenarios`, `POST /scenarios/{id}/publish`, `POST /scenarios/{id}/clone` |
| to `orchestrator` | HTTPS/REST | `GET /scenarios/exam` (случайный экзаменационный) |

## 6. Зависимости и протоколы

| Взаимодействует с | Тип | Протокол |
|---|---|---|
| API Gateway (`gw`) | микросервис | HTTPS/REST, mTLS |
| Session Orchestrator (`orchestrator`) | микросервис | HTTPS/REST, mTLS |
| Picodata (`db`) | СУБД | SQL (PostgreSQL-wire) |
| S3 (Object Storage) | хранилище | S3 API (HTTPS, AWS Signature) |
| Доверенный репозиторий (`repo`) | внешняя система | HTTPS (импорт шаблонов, через Egress) |
| KUMA | SIEM | события ИБ (изменение сценариев/моделей) |

## 7. Данные

- Пикодата: метаданные сценариев, версии, эталоны, связи с тегами.
- S3: бинарные артефакты сценариев/моделей, подписанные.

## 8. Объекты Kubernetes (namespace `ktc-app`)

| Объект | Описание |
|---|---|
| Deployment `scenario` | N≥2, HPA |
| Service `scenario` | ClusterIP |
| NetworkPolicy | accept от `gw` и `orchestrator`; egress к `db`, `s3`, `repo` (через Egress) |
| Pod + sidecar `istio-proxy` | mTLS |

## 9. Метрики (в Astra Monitoring)

- Число сценариев/версий, операции публикации/клонирования.
- Время поиска/выдачи сценария, ошибки целостности.
- События изменения → KUMA.

## 10. Отказоустойчивость / масштабирование

- Stateless, HPA.
- Высокая надёжность: сценарии — ценный актив; резервные копии Picodata + репликация S3.
- Аудит изменений обязателен (коммерческая тайна).

## 11. Открытые вопросы

1. Формат хранения сценария (канонический JSON + версия схемы).
2. Механизм подписи моделей/сценариев (ГОСТ) и проверка при загрузке.
3. Права «бережливого» клонирования между инструкторами.
