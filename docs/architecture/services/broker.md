# Сервис: Брокер сообщений — NATS JetStream

> Инфраструктурный (асинхронная шина/очередь) | Клиент: `:4222` | Монитор: `:8222`
> Управляется слоем инфраструктуры (`data`); конфигурация — `nats.conf` (JetStream).

## 1. Назначение

**«Почтовая служба»** — асинхронная шина и очередь задач. Развязывает сервисы: тяжёлая /
неблокирующая обработка (отчёты, ИИ) и события сессий выполняются асинхронно, не мешая
real-time контуру. Это **не** система хранения бизнес-данных; события дублируются в Picodata/KUMA.

## 2. Основные функции

- **Очередь задач**: отчёты, ИИ-расчёты/инференс.
- **События сессий**: старт/стоп/чекпоинт, авария (для инструктора/аудита).
- Гарантированная доставка (JetStream), retry, приоритеты.
- Развязка publisher/subscriber между сервисами.

## 3. Технологии / конфигурация

**NATS JetStream** (включён в `nats.conf`: `jetstream {}`). Ключевые параметры конфига:

| Параметр (nats.conf) | Назначение |
|---|---|
| `port: 4222` | клиентский порт |
| `http_port: 8222` | HTTP-монитор |
| `jetstream.store_dir` | каталог file store |
| `jetstream.max_mem_store` / `max_file_store` | лимиты хранения (напр. 256 MB / 2 GB) |

## 4. Топики / очереди

| Очередь/топик | Продюсер → Потребитель |
|---|---|
| `report.tasks` | orchestrator → report (queue group `report-workers`) |
| `ai.tasks` | orchestrator → ai |
| `session.events.{id}` | orchestrator → assessment/инструктор |

## 5. Потребители

- `report` — consumer `report.tasks` (группа `report-workers`), генерирует PDF.
- `ai` — consumer задач инференса.
- `orchestrator` — producer событий сессии и задач.

Продюсеры/потребители настраивают subject и queue group в своих TOML-конфигах
(у `report`: `report_tasks_subj`, `queue_group`; у `orchestrator`: `[nats] url`).

## 6. Метрики

- Длина стримов, rate сообщений, задержка доставки, время обработки задач report/ai, отказы/ретраи.

## 7. Отказоустойчивость

- JetStream гарантирует персистентность (file store) и переживает рестарт.
- Масштабирование потребителей (report/ai) по длине очереди.
