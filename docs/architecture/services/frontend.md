# Сервис: Frontend / Web-HMI (SPA) — `fe`

> Слой: Прикладной | Namespace: `ktc-app` | Под: `fe`

## 1. Назначение

Браузерный интерфейс тренажёра — то, что видит и чем управляет пользователь. Включает **конструктор установок** (инструктор собирает мнемосхему вручную) и **HMI оператора** (тренировка/экзамен). Это **тонкий клиент**: никакой «истины» не считает, только отображает серверное состояние и отправляет команды (server-authoritative).

## 2. Основные функции

### Модуль «Конструктор» (Инструктор):
- **Canvas** для drag-and-drop размещения компонентов из палитры (библиотека).
- Палитра компонентов с фильтрацией по категориям (ЭЛОУ / Атмосфера / ГДМ / Общие).
- **Ручное соединение портов** — провод от порта к порту с проверкой типов.
- Панель свойств: параметризация каждого экземпляра при выделении.
- Сохранение шаблона (граф + layout) через REST → `constructor` service.
- Копирование / удаление шаблонов.

### Модуль «HMI оператора» (Оператор):
- Рендер **мнемосхемы** из сохранённого layout шаблона.
- Обновление мнемосхемы по **телеметрии 1 Гц** (WebSocket).
- Панели **трендов** (до 8 серий), **алармов** (HH/H/L/LL) и **faceplate**-узлов.
- Управляющие команды (задвижки, клапаны, регуляторы) → сервер.
- Экран экзамена: таймер, режим «экзамен», запрет подсказок.

### Модуль «Наблюдение» (Инструктор):
- Подключение к сессии оператора в режиме **read-only**.
- Просмотр телеметрии, трендов, алармов без возможности вмешательства.
- Список активных сессий операторов.

### Модуль «Администрирование» (Админ):
- Просмотр пользователей и ролей (учётки и роли ведутся в LDAP/AD сторонним сервисом, CRUD вне платформы).
- Настройка политики оценки и экзаменационных правил.
- Жёсткое удаление шаблонов/сценариев/типов компонентов.
- Учебный аудит и контроль качества обучения (отчёты/протоколы).
- Инфраструктурное администрирование (метрики/логи кластера) — вне роли Админа.

## 3. Технологии

React + TypeScript, Vite, WebSocket-клиент, Konva (canvas для конструктора и мнемосхемы), uPlot (тренды), Ant Design (UI-компоненты).

## 4. Внутренняя структура

- Статический SPA (собранные JS/CSS), раздаётся как статика через Gateway.
- Модули: конструктор (canvas + палитра + свойства), HMI (мнемосхема + тренды + алармы + faceplates), наблюдение, администрирование, WebSocket-подсистема.
- Хранение состояния клиента — Zustand (только кэш отображения, не источник истины).

## 5. API / контракты (клиент → сервер)

| Направление | Протокол | Методы/события |
|---|---|---|
| Конструктор (CRUD) | HTTPS/REST | GET/POST/PUT/DELETE /api/templates, /api/components |
| Сценарии | HTTPS/REST | GET/POST/PUT/DELETE /api/scenarios |
| Сессии | HTTPS/REST | POST /api/session/start, /stop, /pause, set_speed |
| Команды оператора | HTTPS/REST | POST /api/session/{id}/actuator |
| Телеметрия (push) | WebSocket (WSS) | получение тегов/алармов 1 Гц, статусы сессии |
| Наблюдение инструктором | WebSocket (WSS) | read-only подписка на телеметрию сессии |

## 6. Зависимости и протоколы

| Взаимодействует с | Тип | Протокол |
|---|---|---|
| Пользователь (браузер АРМ) | клиент | HTTPS (TLS 1.2+), WSS |
| API Gateway / BFF (`gw`) | микросервис | HTTPS/REST (JSON), WSS (через Ingress + mesh) |
| Istio Ingress Gateway | инфраструктура mesh | HTTP, mTLS (внутри сетки) |
| Пульт / Fluent Bit | observability | `/metrics`, логи stdout |

**Никогда** не общается напрямую с `sim`, `db`, `auth`, `assessment`, `constructor` — только через `gw`.

## 7. Данные (что хранит/видит)

- Не хранит бизнес-данные. Хранит только локальное состояние отображения (кэш).
- Персональные данные (логин) — только отображение; источник — `auth`.

## 8. Объекты Kubernetes (namespace `ktc-app`)

| Объект | Описание |
|---|---|
| Deployment `fe` | N≥2 реплики (статический SPA), RollingUpdate |
| Service `fe` | ClusterIP, доступ из ingress/gateway |
| HorizontalPodAutoscaler | по CPU/памяти |
| PodDisruptionBudget | minAvailable для стабильности |
| serviceAccount + NetworkPolicy | только egress к `gw` (внутри mesh) |
| Pod + sidecar `istio-proxy` | mTLS |

## 9. Метрики (в Пульт + Графиня)

- Время отклика UI (PERF-01 ≤ 500 мс).
- Число активных WebSocket-соединений (операторы + инструкторы).
- Ошибки рендера, latency.

## 10. Отказоустойчивость / масштабирование

- Несколько реплик (stateless), HPA.
- При падении клиента сессия на сервере продолжается (сервер = источник истины).
- Обрыв ≤3 мин — прогресс сохраняется (серверный чекпоинт), клиент переподключается.

## 11. Открытые вопросы

1. Konva vs Fabric.js для canvas конструктора — производительность при 200+ узлах.
2. Кэширование статики и CDN/SRI.
3. Уровень автономии при «офлайн» (переподключение / чёрный экран).
