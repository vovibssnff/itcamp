# События аудита платформы «Конструктор КТК»

Справочник всех событий аудита, которые эмитят сервисы платформы. События
пишутся в **структурные логи** и собираются **Fluent Bit** для доставки в
**Пульт + Графиня** и **KUMA (SIEM)**.

Есть **два механизма** записи аудита:

1. `shared/audit.Emit` — общий механизм для сервисов (constructor, scenario,
   orchestrator). Пишет ключи `component="audit"`, `event=<name>`, `actor=<инициатор>`
   (из заголовка `X-User-ID`), остальные поля — как атрибуты события.
2. `auth/service.AuditService.Log/LogDetail` — локальный механизм в auth.
   Пишет ключи `component="audit"`, `event=<name>`, `user_id`, `ip`, `ts`.

Формат имени события: `<домен>.<действие>` (например `session.stopped`).
Ниже — сводная таблица и разбивка по сервисам.

## 3. Общий формат записи

**`shared/audit` (constructor, scenario, orchestrator):**

```
component="audit"  event="<name>"  actor="<X-User-ID>"  <атрибуты...>
```

**auth (`AuditService`):**

```
component="audit"  event="<name>"  user_id="<id>"  ip="<ip>"  ts="<UTC>"
```

Транспорт до SIEM: **Fluent Bit** → **Пульт + Графиня** (хранение/визуализация) и
**KUMA** (Security Incident & Event Management). Настройка сбора логов — в
[`components/fluent_bit.md`](components/fluent_bit.md).

## 4. Примечания и открытые вопросы

- В **auth** часть событий задекларирована, но ещё не эмитится
  (`login.failed`, `user.created/updated/deleted`, `user.roles_changed`,
  `logout`, `token.revoked`) — по мере развития кода их нужно подключить.
- В сервисах `gw`, `report`, `assessment`, `snapshot`, `sim-manager` на текущий
  момент событий аудита нет (эмитчики `audit.Emit`/`AuditService` там не вызываются).
