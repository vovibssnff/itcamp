# Сервис: Scenario / Catalog Service — `scenario`

> Слой: Прикладной | Namespace: `ktc-app` | Под: `scenario`

## 1. Назначение

**Библиотека и каталог** учебных сценариев и эталонов оценки. Сценарий привязан к шаблону установки (из `constructor`) и содержит набор неисправностей с триггерами (по времени / по условию).

## 2. Основные функции

- CRUD сценариев: создание, редактирование, удаление, копирование.
- Сценарий привязан к **шаблону установки** (из `constructor`).
- Хранение **каталога неисправностей** и эталонов оценки.
- Неисправности в сценарии задаются с **триггерами**: по модельному времени или по условию (значение тега).
- **RBAC**: инструктор правит только свои сценарии.
- Контроль **целостности** сценариев (SHA-256).
- Экзаменационные сценарии: случайная выдача оркестратору.

## 3. Технологии

Python/FastAPI. Хранилище сценарных JSON/артефактов в S3 (MinIO), метаданные в Picodata.

## 4. Внутренняя структура

- Менеджер каталога (CRUD сценарных сущностей).
- Каталог неисправностей (fault_id, description, affected_tags, severity).
- Триггер-движок: задание условий срабатывания (time-based / condition-based).
- Экспорт «готового сценария с эталоном» оркестратору.
- Модуль проверки целостности (SHA-256).

## 5. API / контракты

| Направление | Протокол | Методы |
|---|---|---|
| от `gw` | HTTPS/REST | `GET/POST/PUT/DELETE /scenarios`, `POST /scenarios/{id}/clone` |
| от `orchestrator` | HTTPS/REST | `GET /scenarios/{id}` (полный сценарий с триггерами), `GET /scenarios/exam` (случайный экзаменационный) |

## 6. Зависимости и протоколы

| Взаимодействует с | Тип | Протокол |
|---|---|---|
| API Gateway (`gw`) | микросервис | HTTPS/REST, mTLS |
| Session Orchestrator (`orchestrator`) | микросервис | HTTPS/REST, mTLS |
| Constructor Service (`constructor`) | микросервис | HTTPS/REST (привязка к шаблону), mTLS |
| Picodata (`db`) | СУБД | SQL (PostgreSQL-wire) |
| S3 / MinIO | хранилище | S3 API (HTTPS) |
| KUMA | SIEM | события ИБ (изменение сценариев) |
| Пульт / Fluent Bit | observability | логи, `/metrics` |

## 7. Данные

- Picodata: метаданные сценариев, эталоны, каталог неисправностей, связи с тегами и шаблонами.
- S3 (MinIO): бинарные артефакты сценариев (если есть).

## 8. Объекты Kubernetes (namespace `ktc-app`)

| Объект | Описание |
|---|---|
| Deployment `scenario` | N≥2, HPA |
| Service `scenario` | ClusterIP |
| NetworkPolicy | accept от `gw`, `orchestrator`; egress к `db`, `s3`, `constructor` |
| Pod + sidecar `istio-proxy` | mTLS |

## 9. Метрики (в Пульт + Графиня)

- Число сценариев, операции CRUD/клонирования.
- Время поиска/выдачи сценария, ошибки целостности.
- События изменения → KUMA.

## 10. Отказоустойчивость / масштабирование

- Stateless, HPA.
- Высокая надёжность: сценарии — ценный актив; резервные копии Picodata + репликация S3.
- Аудит изменений обязателен.

## 11. Открытые вопросы

1. Формат хранения сценария (канонический JSON-схема триггеров и неисправностей).
2. Максимальное число неисправностей в одном сценарии.
3. Права клонирования между инструкторами.
