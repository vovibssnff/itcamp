# Сервис: Брокер сообщений — `broker`

> Слой: Инфраструктурный (шина/очередь) | Namespace: Target — `ktc-infra` (прототип — `ktc-app`) | Под: `broker`

## 1. Назначение

**«Почтовая служба»** — асинхронная шина и очередь задач. Развязывает сервисы: тяжёлая/неблокирующая обработка (отчёты, ИИ) и события сессий выполняются асинхронно, не мешая real-time контуру.

## 12. Размещение и обоснование (почему НЕ в слое данных)

- **Брокер — это НЕ данные.** Слой `ktc-data` (Picodata/Radix/S3) — персистентность (хранилище). Брокер — **асинхронный транспорт/очередь между сервисами** (временная персистентность очередей), другая природа.
- **Брокер обслуживает связи прикладных сервисов** (`orchestrator → report/ai`, `assessment`), т.е. находится «в середине» потоков, а не на «конце» (как БД).
- **Задержка и сеть:** производители/потребители рядом; изолированный сегмент добавляет latency без пользы.

**Вывод (Target):** размещать в **отдельном инфра-сегменте `ktc-infra`**. В прототипе для простоты допустим `ktc-app`.

| Вариант | Где | Оценка |
|---|---|---|
| `ktc-infra` (Target) | отдельный инфра-сегмент | **рекомендуется** |
| `ktc-app` (прототип) | вместе с прикладными | приемлемо на MVP |
| `ktc-data` | к Picodata/Radix | смешение «шины» и «хранилища» |

## 2. Основные функции

- **Очередь задач**: отчёты, ИИ-расчёты/инференс.
- **События сессий**: старт/стоп/чекпоинт, авария (для инструктора/аудита).
- Гарантированная доставка, retry, приоритеты.
- Развязка publisher/subscriber между сервисами.

## 3. Технологии

**NATS JetStream**. Обоснование: лёгкий встраиваемый брокер, низкий latency (<1 мс для pub/sub), JetStream обеспечивает гарантированную доставку и персистентность, нативная поддержка K8s, минимальное потребление ресурсов.

## 4. Внутренняя структура

- Стримы (JetStream) для задач и subject-based pub/sub для событий.
- Продюсеры: `orchestrator` (события), `gw` (запросы отчёта).
- Потребители: `report` (задачи PDF), `ai` (задачи инференса), `assessment` (события).
- `/metrics` для состояния стримов.

## 5. Контракты/очереди

| Очередь/топик | Продюсер → Потребитель | Протокол |
|---|---|---|
| `report.tasks` | gw/orchestrator → report | NATS JetStream |
| `ai.tasks` | orchestrator → ai | NATS JetStream |
| `session.events` | orchestrator → assessment/инструктор | NATS JetStream |
| `assessment.events` | assessment → аудит | NATS JetStream |

## 6. Зависимости и протоколы

| Взаимодействует с | Тип | Протокол |
|---|---|---|
| Session Orchestrator (`orchestrator`) | микросервис | producer — NATS |
| Reporting (`report`) | микросервис | consumer — NATS JetStream |
| AI Service (`ai`) | микросервис | consumer — NATS JetStream |
| Assessment Engine (`assessment`) | микросервис | producer/consumer — NATS |
| Пульт (коллектор) | observability | `/metrics` |

## 7. Данные

- Кратковременное хранилище сообщений в JetStream стримах.
- Не является системой хранения бизнес-данных; события дублируются в Picodata/KUMA.

## 8. Объекты Kubernetes

| Объект | Описание |
|---|---|
| StatefulSet `nats` | кластер NATS (N≥3 для отказоустойчивости) |
| Service `broker` | ClusterIP |
| PersistentVolume(s) | для JetStream file store |
| Secret | учётные данные nkey/token |
| Pod + sidecar `istio-proxy` | mTLS |

## 9. Метрики (в Пульт + Графиня)

- Длина стримов, rate сообщений, задержка доставки.
- Время обработки задач report/ai.
- Отказы/ретраи.

## 10. Отказоустойчивость / масштабирование

- Кластер NATS (N≥3) — Raft-репликация JetStream, отказ одной ноды не теряет данные.
- Приоритизация задач; retry упавших.
- Масштабирование потребителей (report/ai) по длине очереди.

## 11. Открытые вопросы

1. Расположение: Target — отдельный `ktc-infra`; прототип допустимо `ktc-app`.
2. JetStream retention policy (limits vs interest vs work queue) для каждого стрима.
3. Поток событий для аудита в KUMA — дублирование через broker или напрямую из сервисов.
