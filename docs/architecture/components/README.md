# Сторонние инфраструктурные компоненты

Обоснование выбора и использования **внешних/инфраструктурных компонентов**
платформы «Конструктор КТК». Подробное обоснование сервисов — в
[`services/`](../services/), общая архитектура — в [ARCHITECTURE.md](../ARCHITECTURE.md).

| Компонент | Слой | Роль | Документ |
|---|---|---|---|
| **Picodata** | Данных `ktc-data` | СУБД, источник правды (история, ядро бизнес-данных) | [picodata.md](picodata.md) |
| **Radix** | Данных `ktc-data` | Кэш, «горячее» состояние сессий | [radix.md](radix.md) |
| **MinIO (S3)** | Данных `ktc-data` | Объектное хранилище (снапшоты, PDF, иконки) | [minio_s3.md](minio_s3.md) |
| **NATS JetStream** | Инфра `ktc-obs`/`ktc-infra` | Асинхронная шина/очередь задач | [nats.md](nats.md) |
| **Пульт + Графиня** | Observability `ktc-obs` | Мониторинг/визуализация метрик | [pult_graphinya.md](pult_graphinya.md) |
| **Fluent Bit** | Observability `ktc-obs` | Сбор и маршрутизация логов | [fluent_bit.md](fluent_bit.md) |
| **LDAP / AD** | Внешний контур | Единый источник учётных записей | [ldap.md](ldap.md) |

## Сводная таблица решения «данных»

| Компонент | Что хранит | Почему именно он |
|---|---|---|
| **Picodata** | история, графы, сессии, оценки, журналы | ФСТЭК/РРПО, PG-совместимость, Raft из коробки |
| **Radix** | горячее состояние (телеметрия, статус сессий) | быстрый Redis-совместимый кэш, единый вендор с СУБД |
| **MinIO/S3** | крупные бинарные объекты | иммутабельные объекты, S3 API, ёмкость |

**Логика разделения (ключевая):** для данных важно **не смешивать** роли:

- **Picodata** — «навсегда/история», источник правды;
- **Radix** — «сейчас/секунды», быстрый кэш (не грузит СУБД);
- **MinIO** — «большие файлы», объекты вне строковой БД;
- **NATS** — не данные, а асинхронный транспорт между сервисами.

## Как это связано со слоями и сервисами

```
ktc-app   (gw, auth, constructor, scenario, orchestrator, assessment, report, snapshot)
   │  ──→ Picodata (своя часть истории)
   │  ──→ Radix    (orchestrator: телеметрия + read-through кеш сессий)
   │  ──→ MinIO    (snapshot: снапшоты; report: PDF; constructor: иконки)
   │  ──→ NATS     (orchestrator→report/ai/assessment)
   │  ──→ LDAP→auth (только auth ходит во внешний AD)
   └──────→ Пульт+Графиня (метрики всех + инфраструктуры)
          └→ Fluent Bit (логи → Пульт + KUMA)
```

Каждый документ содержит: назначение, **обоснование выбора** (почему этот компонент
и почему лучше альтернатив), размещение, реализацию в коде, метрики в Пульт+Графиня,
отказоустойчивость и открытые вопросы.
