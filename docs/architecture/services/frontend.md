# Сервис: Frontend / Web-HMI (SPA) — `frontend`

> Стек: React + TypeScript + Vite + Angie | HTTP: `:8090` | Каталог: `frontend/`

## 1. Назначение

Браузерный интерфейс тренажёра — то, что видит и чем управляет пользователь: конструктор
установок (инструктор собирает мнемосхему), HMI оператора (тренировка/экзамен), набор
экранов администрирования и отчётов. Это **тонкий клиент** (server-authoritative): не
считает никакой «истины», отображает серверное состояние и отправляет команды.

Реализация: **React + TypeScript, Vite**, WebSocket-клиент, Konva (canvas), uPlot (тренды),
Ant Design (UI). Раздаётся как статический SPA сервером **Angie**, который проксирует
`/api` → `gw`.

## 2. Основные функции

### Модуль «Конструктор» (Инструктор)
- Canvas drag-and-drop из палитры (библиотека), соединение портов с проверкой типов.
- Панель свойств, сохранение шаблона (граф + layout), копирование/удаление.

### Модуль «HMI оператора» (Оператор)
- Рендер мнемосхемы из layout, обновление по телеметрии 1 Гц (WebSocket).
- Тренды (до 8 серий), алармы (HH/H/L/LL), faceplate-узлы.
- Управляющие команды (задвижки, клапаны, регуляторы) → сервер.
- Экран экзамена: таймер, запрет подсказок.

### Модуль «Наблюдение» (Инструктор)
- Read-only подключение к сессии оператора: телеметрия, тренды, алармы.

### Модуль «Администрирование» (Админ) + отчёты
- Пользователи/роли, политика оценки, удаление шаблонов/сценариев.
- **Экран отчётов** (`/reports`): список/поиск/скачивание PDF-протоколов.

## 3. Внутренняя структура

- Статический SPA (собранные JS/CSS), раздаётся Angie; прокси `/api` → `gw`.
- Модули: конструктор, HMI (мнемосхема + тренды + алармы), наблюдение, администрирование, отчёты, WebSocket-подсистема.
- Хранение состояния клиента — Zustand (только кэш отображения, не источник истины).

## 4. Конфигурация

Конфигурация — **build-time переменные Vite** (в `frontend/.env.*`):

| Переменная | Назначение |
|---|---|
| `VITE_API_BASE_URL` | Базовый REST API. Пусто → same-origin `/api` через Angie-прокси |
| `VITE_WS_BASE_URL` | Базовый WS. Пусто → same-origin |
| `VITE_MOCK_API` | `true` → MSW REST-моки + mock WebSocket (без бэкенда) |
| `VITE_DEV_PROXY_TARGET` | Vite `/api` прокси (dev, по умолч. `http://localhost:8088`) |

Для hot-reload (без сборки):

```bash
cp -n .env.development.example .env.development
pnpm install && pnpm openapi:gen && pnpm dev
```

Regenerate типов OpenAPI из `services/go/*/api/openapi.yaml`:

```bash
pnpm openapi:gen
```

Скрипты: `pnpm dev`, `build`, `typecheck`, `test`, `e2e`.

## 5. API / контракты (клиент → сервер)

| Направление | Протокол | Методы/события |
|---|---|---|
| Конструктор (CRUD) | HTTPS/REST | GET/POST/PUT/DELETE /api/templates, /api/components |
| Сценарии | HTTPS/REST | GET/POST/PUT/DELETE /api/scenarios |
| Сессии | HTTPS/REST | POST /api/session/start, /stop, /pause, set_speed |
| Команды оператора | HTTPS/REST | POST /api/session/{id}/actuator |
| Отчёты | HTTPS/REST | GET/POST /api/reports, /{id}/download |
| Телеметрия (push) | WebSocket | теги/алармы 1 Гц, статусы сессии |
| Наблюдение инструктора | WebSocket | read-only подписка |

## 6. Данные

- Не хранит бизнес-данные, только локальное состояние отображения (кэш).

## 7. Метрики

- Время отклика UI, число активных WebSocket-соединений (операторы + инструкторы).
- При падении клиента сессия на сервере продолжается (сервер = источник истины).
