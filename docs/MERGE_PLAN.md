**Дата:** 2026-08-06

## Принятые решения

| # | Вопрос | Решение |
|---|--------|---------|
| 1 | Аутентификация | **JWT-only**, без LDAP/AD/PAM/2FA |
| 2 | Сервис конструктора | **Отдельный сервис `constructor`** (backend для библиотеки, шаблонов, графа) |
| 3 | Протоколы внутри | **Из архитектуры**: REST между сервисами, gRPC только для sim (Model API) и ai |
| 4 | Service Mesh / Ingress | **Istio** (Ingress Gateway + mTLS sidecar) + **Angie** как BFF внутри |
| 5 | Брокер | **NATS** |
| 6 | Мониторинг | **Пульт** (метрики, Prometheus-совместимый) + **Графиня** (визуализация) |
| 7 | Роли | **3 роли: Админ, Инструктор, Оператор** |
| 8 | Инструктор и неисправности | Инструктор **только наблюдает** сессии. Неисправности — **только из сценария** (по времени/условию, автоматически) |
| 9 | Sim topology | **1 pod per session** (решение по оптимизации — позже) |
| 10 | S3 хранилище | **MinIO** (заглушка/on-prem); в target — отечественное S3-совместимое |
| 11 | SIEM | **KUMA** (Kaspersky) — добавляем в стек |
| 12 | Мнемосхема | **Ручная сборка** инструктором (drag-and-drop на canvas), никакой авто-генерации |
| 13 | Версионирование | **Убираем**. Только CRUD для шаблонов и компонентов |
| 14 | Kubernetes | **Deckhouse** (как в SRD) |

## Этап 1: Правки архитектуры (docs/architecture/)

### 1.1. `auth.md` — убрать LDAP, оставить JWT-only

**Удалить:**
- Интеграция с LDAP/AD
- 2FA (TOTP), PAM
- Синхронизация с корпоративным каталогом
- Зависимости: LDAP/LDAPS, Egress Gateway для LDAP, PAM

**Оставить/добавить:**
- Локальная база пользователей в Picodata (login, password_hash, role)
- Выдача/проверка JWT (access + refresh)
- RBAC по 3 ролям (Админ, Инструктор, Оператор)
- Логаут, ротация refresh-токенов
- Аудит входов → KUMA

---

### 1.2. Создать `constructor.md` — новый сервис

**Назначение:** Backend для визуального конструктора установок и управления библиотекой компонентов.

**Функции:**
- CRUD библиотеки компонентов (типы оборудования, порты, параметры, иконки)
- CRUD шаблонов установок (граф: узлы + рёбра + параметры + layout мнемосхемы)
- Валидация графа (типы портов, связность, обязательные элементы)
- Копирование шаблонов
- Экспорт шаблона в формат для sim (Model API init state)
- Фильтрация/поиск по библиотеке (категории: ЭЛОУ, Атмосфера, ГДМ, Общие)

**Зависимости:** Picodata (хранение), S3 (иконки/артефакты), gw (REST API)

---

### 1.3. `broker.md` — зафиксировать NATS

- Заменить «RabbitMQ / Kafka / NATS» → **NATS JetStream**
- Протокол: NATS native (не AMQP, не Kafka binary)
- Обоснование: лёгкий, встраиваемый, JetStream для гарантий доставки, низкий latency

---

### 1.4. Все файлы — мониторинг

Заменить:
- «Astra Monitoring» → «Пульт + Графиня»
- «promColl» → «Пульт (коллектор метрик)»
- «Fluent Bit» — оставить (сбор логов; Пульт для метрик, KUMA для ИБ-событий)

---

### 1.5. Все файлы — роли

Заменить:
- «Ученик/Инструктор/Админ/Наблюдатель» → «Оператор/Инструктор/Админ»
- Убрать: Наблюдатель (функция наблюдения есть у Инструктора), Методист, Главный инструктор
- Инструктор: создаёт шаблоны, сценарии, наблюдает сессии, запускает экзамены, оценивает
- Оператор: проходит тренировку/экзамен
- Админ: управление пользователями, платформой, конфигурацией

---

### 1.6. `session_orchestrator.md` — убрать динамическую инъекцию

**Удалить:**
- `inject_fault` из API оркестратора (инструктор → сессия)
- Любые упоминания «инструктор вносит неисправность в реальном времени»

**Изменить:**
- Неисправности приходят из **сценария**: таймер / условие → orchestrator вызывает `sim.inject_fault(fault_id)` автоматически
- Инструктор подключается к сессии в режиме **read-only** (наблюдение телеметрии через WS)

---

### 1.7. `frontend.md` — конструктор вместо фиксированной мнемосхемы

**Добавить модуль «Конструктор»:**
- Canvas (Konva/Fabric.js) для drag-and-drop размещения компонентов
- Палитра компонентов (из библиотеки, фильтр по категориям)
- Ручное соединение портов (провод от порта к порту)
- Параметризация экземпляров (панель свойств при выделении)
- Сохранение layout мнемосхемы как часть шаблона

**Убрать:**
- «Автоматическая генерация мнемосхемы из графа»

---

### 1.8. `scenario_catalog.md` — уточнить роль

- Сценарий привязан к шаблону установки (из `constructor`)
- Сценарий содержит: список неисправностей + триггеры (время/условие) + эталонные действия
- Убрать Low-Code конструктор сценариев (если его нет — уточнить) → оставить CRUD + шаблоны

## Этап 2: Правки SRD (docs/SRD-Конструктор-КТК.md)

### 2.1. Ролевая модель → 3 роли

Удалить из SRD: Главный инструктор, Методист, Наблюдатель.  
Перераспределить функции:
- Методист → Инструктор (создание шаблонов, сценариев, оценка)
- Наблюдатель → Инструктор (read-only наблюдение)
- Главный инструктор → Админ (управление доступом)

---

### 2.2. Убрать динамическую инъекцию неисправностей

Удалить/переписать:
- Раздел FR-INJECT-* (динамическая инъекция инструктором)
- Упоминания «инструктор вносит неисправности в реальном времени»

Заменить на:
- Неисправности задаются при создании сценария (время/условие)
- Во время сессии срабатывают автоматически
- Инструктор наблюдает, но не вмешивается

---

### 2.3. Убрать версионирование

Удалить:
- FR-LIB-03 (версионирование компонентов)
- FR-TMPL-06 (версионирование шаблонов)
- Упоминания `schema_version`, миграции, обратной совместимости

Оставить: CRUD (создать, читать, обновить, удалить, копировать).

---

### 2.4. Убрать авто-генерацию мнемосхемы

Удалить:
- FR-CNST-05 (автоматическая генерация мнемосхемы из графа)

Заменить:
- Инструктор вручную размещает компоненты на canvas, соединяет порты, настраивает layout

---

### 2.5. Добавить в стек

| Компонент | Назначение |
|-----------|-----------|
| Istio | Service Mesh: mTLS, Ingress Gateway, traffic policies |
| NATS JetStream | Брокер сообщений / очередь задач |
| KUMA (Kaspersky) | SIEM: аудит ИБ-событий |
| MinIO | S3-совместимое хранилище (target — отечественное) |
| Пульт + Графиня | Мониторинг метрик + визуализация |

---

### 2.6. Протоколы — из архитектуры

Обновить раздел «Архитектура» SRD:
- Внутри: **HTTPS/REST** (JSON) + **mTLS** (Istio sidecar)
- sim ↔ orchestrator: **gRPC** (Model API)
- ai ↔ orchestrator/assessment: **gRPC** + mTLS
- Наружу (клиент → Istio Ingress): **HTTPS + WSS**
- Брокер: **NATS** native protocol
