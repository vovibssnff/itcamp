# Сервис: AI Service — `ai`

> Язык: Python (FastAPI) | Слой: Машинное обучение | HTTP: `:8089` | Сервис: `services/python/ai`

## 1. Назначение

**«Умный помощник»** — интеллектуальный анализ и генерация поверх детерминированного
ядра оценки. Реализует Explain / Predict / риски / разбор сессии / чат-бот. Должен
**деградировать**: его падение не останавливает симуляцию и rule-based оценку (NFR-REL-03).

Реализация: **Python + FastAPI** (+ gRPC в proto `ktk/ai/v1/ai_service.proto`), LLM через
**Ollama** (или `stub`-провайдер без GPU).

## 2. Ключевой принцип: ИИ аннотирует балл, но не считает его (ADR-001)

```
Детерминированный слой (авторитетный)          ИИ-слой (совещательный)
├── reaction_time.py  время реакции             ├── распознавание эквивалентных стратегий
├── sequence.py       сравнение с эталоном      ├── интерпретация паттернов ошибок
├── scoring.py        итоговый балл      ────►  └── текст разбора и объяснений
└── результат неизменяем                             влияет только на текст, не на балл
```

Время реакции — вычитание меток; сравнение с эталоном — выравнивание последовательностей
(LCS). Оба детерминированы и **не** требуют LLM. Это гарантирует воспроизводимый балл
(важно для HMAC-протокола экзамена) и отказоустойчивость без GPU.

Полезные требования:
- Explain ограничен, в экзамене отключён (`403 EXAM_MODE_BLOCKED`).
- Чат-бот **не видит телеметрию** (ADR-002) и отказывается раскрывать эталон/критерии — работает как открытый справочник.
- **Галлюцинации по тегам** отсекаются машинно: `TagGuard` сверяет упомянутые теги со словарём шаблона и бракует ответ целиком (ADR-003).
- Каждый LLM-вызов имеет предохранитель + детерминированный резерв (ADR-004).

## 3. Основные функции

| Возможность | Как реализовано | Требование |
|---|---|---|
| Анализ действий | выравнивание журнала с эталоном (LCS) | FR-ASSESS-02 |
| Оценка времени реакции | разность модельных меток, норматив квитирования | FR-ASSESS-01 |
| Оценка последовательности команд | «вовремя / не по порядку / пропущено / просрочено» | FR-ASSESS-02/03 |
| Explain | LLM + RAG по регламенту | FR-AI-02 |
| Прогноз выхода на уставку | взвешенная регрессия по тренду (без LLM) | FR-AI-03 |
| Оценка риска действия | правиловый движок + формулировка LLM | FR-AI-04 |
| Чат-бот обучаемого | справочник по регламенту (без телеметрии) | — |
| Разбор сессии | LLM с деградацией до структурного разбора | FR-ASSESS-06/07 |

## 5. Использование RAG

Объяснения (Explain), чат-бот и разбор построены на **RAG** (Retrieval-Augmented
Generation): сначала из базы знаний извлекаются релевантные фрагменты регламента, затем
они передаются LLM как контекст. Это лёгкий **лексический RAG без эмбеддингов и без
векторной БД** — специально под корпус в один технологический регламент.

| Компонент | Файл | Что делает |
|---|---|---|
| Корпус и загрузка | `rag/store.py` | `KnowledgeBase` индексирует `data/regulation/` (`.txt`/`.md`, `.pdf` через pdfplumber) или загружает предсобранный `data/index.jsonl` |
| Чанкинг | `rag/chunker.py` | Документы режутся на фрагменты с метаданными: `source`, `section`, **`equipment`** (аппараты), **`tags`** (приборы) |
| Поиск | `rag/bm25.py` | Кастомный **BM25** с атому-токенами позиций, русским стеммингом и нормализацией омоглифов |
| Фильтрация | `bm25.py:search` | `equipment_filter` (аппараты текущего шаблона) отсекает разделы про оборудование, которого нет в установке |

**Почему BM25, а не векторный поиск.** Корпус — один регламент (сотни чанков), а запросы
обучаемых почти всегда содержат точную позицию прибора/номер аппарата, где **точное
совпадение важнее семантической близости**. Векторный индекс избыточен; интерфейс
`KnowledgeBase.search` готов под его встраивание без изменения кода.

**Особенности токенизации (`bm25.py`):**
- **атомы позиций** — регулярки выделяют цельные токены аппаратов (`К-1`, `Н-2А`) и
  приборов (`FRC 408`, `LRCA-641`), иначе «К-1» развалилось бы на стоп-слово и цифру;
- **русский стемминг** — «противогаз» находит «противогазом», «уставка» — «уставки»;
- **омоглифы** — кириллические «РRС 221» приводятся к единому алфавиту (в регламенте позиции набраны вперемешку);
- **буст `+4`** за совпадение позиции аппарата/прибора поднимает нужный фрагмент в топ.

**Где применяется:**
- `explain.py` — `search(query, top_k=3, equipment_filter)` из тегов/соседей/алярма → контекст для LLM-объяснения;
- `chat.py` — `search(..., equipment_filter)` → релевантные фрагменты для чат-бота (прямая цитата как резерв при отказе LLM);
- `annotate.py` — `search(f"{target} регулирование", top_k=2)` → подбор фрагментов для разбора/аннотаций.

Добавление раздела регламента не требует правки кода: положите файл в `data/regulation/`
и пересоберите индекс (`make index` / `scripts/index_docs.py`).

## 6. Конфигурация

Конфигурация — **env-переменные** (секреты — через секрет-хранилище, не в образ):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `KTK_LLM_PROVIDER` | `stub` | `ollama` или `stub` (работа без GPU) |
| `KTK_LLM_MODEL` | `qwen2.5:14b-instruct` | Модель в Ollama |
| `KTK_OLLAMA_URL` | `http://localhost:11434` | Адрес Ollama |
| `KTK_DOCS_DIR` | `data/regulation` | Справочные материалы для чат-бота |
| `KTK_CHAT_IN_EXAM` | `true` | Работает ли справочник на экзамене (ADR-002) |
| `KTK_BREAKER_FAILURES` | `5` | Порог срабатывания предохранителя |
| `KTK_EXPLAIN_DEADLINE_S` | `12` | Дедлайн вызова Explain |

Добавление разделов регламента не требует правки кода: положите файл в `data/regulation/`
и выполните `make index`.

## 7. API / контракты

| Эндпоинт | Назначение |
|---|---|
| `POST /v1/session/review` | Анализ действий: время реакции, последовательность, балл, аннотации, разбор |
| `POST /v1/explain` | Объяснение аларма (в экзамене — `403 EXAM_MODE_BLOCKED`) |
| `POST /v1/predict/physics` | Прогноз выхода параметра на уставку |
| `POST /v1/predict/behaviour` | Оценка риска действия до подтверждения |
| `POST /v1/chat` | Справочный чат-бот |
| `GET /healthz`, `/readyz`, `/metrics` | Служебные |

Основной транспорт внутри кластера — gRPC (`proto/ktk/ai/v1/ai_service.proto`); REST — для BFF (gw) и отладки.

## 8. Данные

- `data/tags_demo.json` — словарь тегов демо-шаблона с уставками и блокировками из регламента;
- `data/risk_rules.json` — каталог опасных действий;
- `data/regulation/` — текст регламента для чат-бота.
- Picodata: (опционально) кэш результатов/метаданных разбора.

## 9. Метрики / деградация

- GPU utilization/VRAM (если есть), время ответа explain/predict, число запросов, очередь.
- Падение ИИ **не** останавливает симуляцию и rule-based оценку (fallback на детерминированный резерв).
